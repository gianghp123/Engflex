# E2E (Playwright, live backend)

Voice-room flows against a real Go API + Postgres. The voice engine is **not**
started: `VOICE_SERVICE_URL` points at a dead port so setup-failure paths are
deterministic. True mid-call WebRTC disconnects are out of scope.

## Prerequisites

`playwright.config.ts` loads `tests/e2e/.env` (falling back to
`apps/web/.env.local`) via Vite's `loadEnv`; shell env wins on conflict.

```sh
# tests/e2e/.env (gitignored; see .env.example)
VITE_CLERK_PUBLISHABLE_KEY=...
CLERK_SECRET_KEY=...             # same Clerk instance as the apps
DATABASE_URL=postgres://postgres:postgres@localhost:5777/engflex_e2e?sslmode=disable
E2E_CLERK_USER_EMAIL="e2e+clerk_test@…"   # pre-created test user
```

Postgres must be running (`cd apps/api && docker compose up -d postgres`).
`DATABASE_URL` must point at a **dedicated e2e database**: `ensure-e2e-db.mjs`
(chained onto the API's `webServer.command`) creates and migrates it before the
API boots, so tests never touch dev data.

## Run

```sh
cd tests/e2e
pnpm test:e2e            # headless, boots Go API + vite automatically
pnpm test:e2e:headed     # headed browser
pnpm test:e2e:live       # live engine + fake mic (Analyze flow)
pnpm test:e2e:recovery   # live engine + fake mic (transcript recovery)
```

Live suites (`playwright.live.config.ts`, `playwright.recovery.config.ts`) share
one stack on dedicated ports (API 8010, web 3010, engine 7861) and need
`apps/voice/.env` with real `STT_API_KEY`/`LLM_API_KEY` and the voice model in
`models/`.

## Notes

- Fake mic: Chromium's tone-based fake capture is rejected by STT, so the live
  suites feed a 48 kHz WAV generated by `apps/voice/scripts/make_fake_mic_audio.py`.
- `--use-file-for-fake-audio-capture` is silently ignored without
  `--use-fake-device-for-media-stream`.
- Never assert absolute positions — playback phase is uncontrolled; the
  invariant is group ordinal == DB position.
- `global.setup.ts` signs in and stores auth state to
  `playwright/.clerk/user.json` (gitignored).

## Layout

- `global.setup.ts` — Clerk setup, server-side sign-in, storage state.
- `ensure-e2e-db.mjs` — create + migrate the e2e database.
- `helpers.ts` — authed API calls, turn/feedback seeding and read-backs.
- `live-stack.ts` — shared live stack (env, ports, Chrome flags).
- `live-boundaries.mjs` — per-boundary verdict report from a run log + DB.
- `voice-room.spec.ts` — service-fail modal, ended-session review, feedback card.
- `voice-live.spec.ts` — live Analyze suite.
- `voice-recovery.spec.ts` — live transcript-recovery suite.

Desktop Chromium only, one worker (serial against the live backend).
